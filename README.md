# cuven Stream —— Dropbox 视频代理（Cloudflare Worker）

`Stream_v25.js` 是主 Worker（单文件，部署方式与之前完全相同）。v25 起，Safari / iOS 上的
MKV 不再交给浏览器硬解，而是在 Worker 里**实时重封装成 fMP4 HLS**，由系统原生播放器播放，
HDR10、HLG、杜比视界都能真正点亮，并且支持全屏、画中画、AirPlay，以及系统自带的音轨 / 字幕菜单。

| 路径 | 内容 |
| --- | --- |
| `Stream_v25.js` | 主 Worker：Dropbox 代理、`/stream` 直连、MKV → HLS、自带的首页与 `/watch` 播放页 |
| `web/index.html` | 前端（Stream · Cinematic Edition，单文件 SPA），站内播放器，不再依赖 Infuse |
| `audio-tx/` | 可选的 DTS / TrueHD → AC-3 转码 Worker |
| `index/` | Cuven ᴿ 索引库 Worker（论坛 → TMDB → R2 索引，对照片库标出缺片），说明与测试见 [`index/README.md`](index/README.md) |
| `tests/` | 回归测试：Worker（`run.mjs`）与前端（`web.mjs`） |

## MKV → HLS 链路

| 环节 | 做法 |
| --- | --- |
| 入口 | `/hls/<exp>.<sig>.<path>/master.m3u8`（签名写在路径里，与 `/stream` 同一枚 HMAC 签名） |
| 索引 | 读文件头 + Cues + 首簇（3~4 个小 Range），按文件 `content_hash` 缓存 |
| 分段 | 以视频关键帧为界（目标 6 秒，起播前两段 2s / 4s），每段只回源自己那段字节 |
| 回源 | 每段开头 1 MB 直通（压低首字节），其余按 4 MB 切片并行取（默认同时 3 片，`HLS_WINDOW` 可调） |
| 预取 | 第 k 段取完后，后台把第 k+1 段取进边缘缓存；主列表一到就先取第 0 段。播放器来要时：缓存里有就直接出，预取还在半路就等它写完再出（不重复回源）；拖动回看也从缓存出 |
| 缓存 | 只缓存完整写完的段：数据写在一次性的键下，整段正常写完才把「指针」写到这一段的固定键上，半截的数据永远读不到。请求之间只读彼此的进度数字，不跨请求等待 Promise、不共享流；每个 isolate 同时只跑一路预取 |
| 视频 | H.264、HEVC、AV1。不转码，负载零拷贝直通；DTS 由 PTS 与 SPS 重排深度推出，跨分段连续 |
| 参数集 | `CodecPrivate` 里的 hvcC / avcC / av1C 齐全时一个字节不动地用。不齐时（参数集只在码流里的 hev1 / avc3 风格流、整个 `CodecPrivate` 都没有、长度前缀宽度写错）从片头几帧里把 VPS / SPS / PPS（AV1 是序列头 OBU）捞出来，与配置里的按编号合并去重，按 SPS 的 profile / tier / level 重建配置盒（`hvc1` / `avc1` 要求参数集都在配置盒里，苹果只认这一种）。帧里是 Annex B 起始码的，出分段时就地转成 4 字节长度前缀。凑不齐时直接说缺了哪几个 |
| 不支持的编码 | MPEG-2、VC-1、MPEG-4 Part 2（DivX / Xvid）、VP8、VP9、Theora、ProRes 等进不了系统播放器：播放页直接说是哪种编码、建议用 VLC 打开直链 |
| 杜比视界 | P5 → `dvh1`+`dvcC`；P8.1 / 8.4 → `hvc1`+`dvvC`+`SUPPLEMENTAL-CODECS`（`db1p` / `db4h`）；**P7（UHD 蓝光双层）逐帧丢弃增强层并把 RPU 改写为 8.1** |
| HDR | 依 MKV Colour、HEVC / H.264 的 SPS VUI、AV1 的序列头写 `VIDEO-RANGE` 与 `colr` / `mdcv` / `clli`（MKV 没写 Colour 的 HDR 片不会被当成 SDR） |
| 音频直通 | AAC、AC-3、E-AC-3（含 Atmos：`CHANNELS="16/JOC"`）、FLAC、ALAC。默认音轨复用在视频分段里，其余为备选音轨 |
| 备选音轨顺路 | MKV 里音视频交错存放：换到别的音轨后，这条音轨的每一段原来都要把这段字节从 Dropbox 再读一遍、再解析一遍（视频那一遍已经读过），而且从不进缓存。现在有人在听某条备选音轨，就记下来（90 秒没人再要就作罢），之后视频那一遍（直出 / 预取）把它的块一起收下、按原来同一套规则切好写进缓存，音轨请求先等它；视频段已经在缓存里时不等，自己读一遍切好也进缓存。真实 workerd 里 3 分钟多音轨 HEVC 换音轨看一遍：Dropbox 读 237 MB → 122 MB，再看一遍 0 MB；切出来的音轨分段与原来逐字节一致 |
| 音频转码（可选） | DTS、TrueHD、Opus、Vorbis、MP2/MP3、PCM → AC-3 5.1（640 kbps），需要 `audio-tx` Worker |
| 字幕 | 内封 SRT / ASS（含 zlib 压缩）、同目录外挂 `.srt/.ass/.vtt` → 分段 WebVTT（带 `X-TIMESTAMP-MAP`），中文（简体优先）默认开启。没有字幕 Cues 的文件：字幕块在转视频那一遍顺手收下，不再为字幕把整段视频重读一遍 |
| 提效（2026-11） | 用 `tests/bench.mjs` 把样片的每一段都切一遍、量 CPU 后改的几处热点：① 解析 MKV 块时数据已经在队列里就同步往下走（一个元素头原来要 await 三四次，一段几千个块，微任务的来回比解析本身还贵），SimpleBlock 的块头在第一次看的 16 字节里就认出来，不再取第二次；② 杜比视界 P7 的 RPU 改写：同一个镜头里相邻帧的 RPU 往往逐字节相同，同样的输入直接用上一次的输出（比一遍字节，省掉整套位级解析、改写、重算 CRC）；③ 出口不再把每个分片整块拼成一个大缓冲再交给响应流：≥ 16 KB 的切片原样交出，零碎的攒到 64 KB 再拷，4K 片源每段少拷几十 MB、峰值内存少一整个分片；④ HLS 令牌验过一次就在 isolate 里记到过期，同一次播放的几百个请求不再各算一遍 HMAC。测试台上 Worker 自己的 CPU 合计降了一半多（3 分钟多音轨 HEVC + 96 秒杜比视界 P7 + 两部短片：1.7 s → 0.78 s；杜比视界那部 −59%，样片里相邻帧的 RPU 重复得多），真实 workerd 里每一段输出与改动前逐字节一致 |

播放页（`/watch`）、首页弹窗和前端站内播放器在 Apple 的原生播放器（macOS Safari，以及 iOS / iPadOS
上的所有浏览器）里打开 MKV 时自动走这条链路。徽章按码流实测显示（Dolby Vision / HDR10 / HLG）。
签名过期或文件被替换时，会换新签名并从原位置重载。
其它浏览器、MP4/MOV 文件仍走 `/stream` 直连（v24 的 FourCC 热修补照旧生效：`hev1` → `hvc1`、`dvhe` → `dvh1`，
但只在 hvcC 里带齐 VPS / SPS / PPS 时才改名 —— 参数集只在码流里的流改了名，苹果的解码器反而彻底拒播）。新版桌面 Chrome 虽然也
声称支持 HLS，但只要 `CODECS` 里有一个它解不了的编码（例如备选音轨的 `ac-3`）就整条拒播，
杜比视界、AC-3 / E-AC-3 它也解不了，所以不给它 HLS；它能直接播放 MKV。

调试用：`/hls/<token>/info.json` 返回识别结果（编码、HDR / 杜比、各音轨是否可播 / 是否转码）。

## 前端：播放（`web/index.html`）

以前点「播放」是用 `infuse://` 把直链交给 Infuse：没装 Infuse 什么也放不了，续播进度也记在 Infuse 里。
现在全部在页面里完成，详情页保持原样：

- **点「播放」→ 加载画面 → 系统全屏播放器**，没有自绘的播放页与控件：
  - 点下去到真正开播之间是加载画面：背景逐像素复刻 Framer「Aurora Flow」组件（参照 homely-mindset-354396.framer.app
    那一份的参数，两遍 WebGL2，手指按住拖动会扭动光带），中间叠「Cuven max」，下面是 iOS 更新式的胶囊进度条，
    再下面一句句模糊消散、模糊进入地轮播「请保持屏幕亮起 → … → 即将完成」（停在最后一句）。进度按真实阶段推进
    （拿到片源 → 元数据 → 首帧 → 可以播 → 开播），开播前不会走满；开播后背景停止渲染，把 GPU 留给解码。
  - Apple 设备（iPhone / iPad / Mac 的 Safari）：`<video playsinline>` 在点按的手势里就起播，先在加载画面后面缓冲，
    真正开始播放（`playing`）的那一刻调 `webkitEnterFullscreen()` 进系统播放器（杜比视界 / HDR、音轨与字幕菜单、
    画中画、隔空播放都是系统的）。只进一次，之后的缓冲、拖动不会把人拽回全屏。
  - 其它浏览器：点下去的那一刻把播放层整块全屏（加载画面就在全屏里），开播后淡出，用浏览器自带的控件。
  - 关掉系统播放器（「完成」/ 下拉 / Esc / 返回键）就回到原来的页面，底下的详情页原样留着。进画中画时接着放。
  - 全屏进不去时（权限 / 环境不允许），黑底层本身就是一个带原生控件的播放器，照样能看。
- **起播**：打开详情页时就把签名和 HLS 索引（`info.json`）取好。点下去的那一刻片源就有，在同一个手势里设片源、`play()`
  （iOS 从此允许出声播放、之后进全屏不必再要手势）。预热没赶上时，手势里先 `load()` 把元素解锁，片源回来再播。
- **片源**：Safari / iOS 上 MKV 走上面的 HLS 链路，MP4 / MOV 和其它浏览器走 `/stream` 直连。
- **字幕**：HLS 的字幕在主列表的字幕组里，中文（简体优先）默认开启，由系统播放器显示和切换。直连时自动挂上同目录外挂字幕，
  中文默认打开（浏览器按系统语言自己再开一条时会被扳回来，不会两条叠着出）。
- **优选入口**：Worker 配了 `EDGE_HOSTS` 时，页面会在空闲时实测各入口（`/api/edge/ping`），选最快的来放片，6 小时测一次；出错退回默认入口。
- **续播**：进度记在本地（`play_progress_v1`）：每 5 秒、暂停、关闭、切到后台各记一次。再次打开从上次的位置继续；
  看完自动清掉。「继续观看」卡片上有进度条。
- **剧集**：播完在系统播放器里直接接下一集（快播完时就把下一集预热好）。
- **出错**：签名过期或网络中断时，换新签名从原位置重连（最多两次）。文件本身转不了 HLS（比如缺 Cues）时，直接显示原因。
- **iPhone Duo**：按 Safari 27.1 实测视口适配：折起竖拿 382×580（加到主屏幕的 App 里是 466×678）、折起横拿 594×368、
  展开竖拿 669×825、展开横拿 951×543。
  - **全新导航栏（折起竖拿）**：底部那条胶囊换成贴右缘浮着的一枚竖向玻璃胶囊，只放图标，自上而下是主页、资料库、搜索，
    头像（圆角方块）垫在最底；选中那一项是白色图标 + 一圈柔光圆底，其余是灰色，文字收起（读屏照读），右手拇指一伸就到。

  片名里带年份的（《银翼杀手2049》《神奇女侠1984》）被截断、同名不同年与续集（《沙丘》1984 / 2021、《玩具总动员 3 / 4》）
  常认成更热门的那部、电影搜不到就随便拿一部剧顶上、详情页的 iTunes 海报也按片名拿第一条。现在：
  - 解析：中文名与英文名分开、上映年取最后一个合理的年份（片名里的年份留在片名里）、截到规格词或季集号为止、
    剥掉版本词（加长版、导演剪辑版…）、方括号里的站名与字幕组扔掉；样片 / 预告 / 花絮直接不认。
  - 打分：中英两种语言各搜一次、候选合并，按片名相似度（中文名 / 英文名 / 原名；罗马数字、数字词、全角、标点、
    变音符归一；续集号对不上压分）、年份（差两年以上压到认不上）、类型、票数打分；分数不够就不认。拿不准但年份对得上的，
    再取别名表与各语言译名（罗马音、繁体）比一次。电影认不上时只认片名几乎一样、首播正好那年的剧集。
  - iTunes 海报要片名、年份都对得上才用，而且只换海报，横向背景仍用 TMDB 的剧照。TMDB 没有海报时先用 iTunes 补。
  - TMDB 出错与「认不出」分开：批接口出错的那几项不回（前端过会儿再问），`__match: 2` 标明这里的 null 是确定的答案；
    出错不进缓存。缓存换代（后端 `tmdb-v9`、前端 `tmdb_cache_v8` / `cn_title_index_v2` / `itunes_cache_v2`），
    旧算法认错的结果整批重认（v9 / v8 起简要结果也带类型）；剧集表的 TMDB 信息也整批重认，剧照按剧集表认好的编号取
    （`/api/tmdb?id=&type=tv`）。
  - 总账（旧版后端算的 R2 副本）里年份与文件名差一年以上的那条不信，交给现在的匹配管线重认。
- **没有封面的影片 / 剧集不显示**：只认确定的答案 —— 后端明确说认不出，或认出来了但没有海报（iTunes 也补不上）；
  网络出错、超时不算。首页各排、今日推荐（名次重排）、首页大图、资料库、年份 / 文件夹页、搜索、剧集区都不排；
  已经在屏上的卡，答案一到就收起来（淡出 + 收拢，旁边的卡平滑靠过来，开着 scroll-snap 的行不会被带跑），
  一排收空了整段藏起来。答案记在本地三天，之后再问一次（TMDB 上可能补了海报）。
- **登录页**：上半截是品牌区 —— Sky Pro 流体底图从白色面板上沿露出来，居中 Cuven max 字标，左上角圆形关闭 / 返回钮，
  打开时与登录成功时蓝色脉冲从字标向外扩。下半截是一整张白色圆角面板：「Cuven 账户」小字标、左对齐的大标题
  （输入电子邮件以继续）、浅灰填充的输入框、黑色胶囊主按钮、分割线、Cuven 账户体系说明；验证码、设定密码、面容 ID、
  成功页同一套样式。手机上面板贴到屏底、内容在面板里滚，输入法弹起时品牌区让出来；平板与 Mac 上收成居中的一张卡；
  矮横屏上字标压成一行、内容收在中间。
- **预告片**：资料库展厅的预告片原来全部来自 IMDb，而 IMDb 现在不接 Cloudflare Worker 的请求（每部片都回空，展厅只剩剧照）。
  现在 IMDb 给得出直链 MP4 时照旧用直链；给不出就用 TMDB 登记的 YouTube 官方预告（正式预告优先、官方优先、中文略优先），
  套成与 `<video>` 同样的接口放：静音自动开播、从第 3 秒进、进度环、取消静音、给播放器让路都与直链一致，
  不经过 HLS，也不经过 Worker。地址晚到时条件一凑齐就挂上开播。「减弱动态效果」不再挡掉预告片（原来连播放钮都按不动）；
  省流量 / 弱网时只放剧照。
  - YouTube 自己的界面一样都不露，背景只有画面：手机上的嵌入播放器不认 `controls=0` —— 一开播、一恢复播放，片名条和
    「上一个 / 暂停 / 下一个」要亮两三秒，一暂停就铺满「More videos」和 YouTube 标志，片尾还有上传者的订阅 / 推荐画面。
    现在画面连续播满 3 秒、那层控件自己退掉以后才淡入（之前露的是这一章的剧照）；要暂停时先把画面隐去再让它停；
    缓冲卡住超过 0.7 秒先隐去；片尾 12 秒（短片 1.5 秒）之前先隐去、回卷到第 3 秒；字幕模块整个卸掉（系统语言触发的自动字幕
    `cc_load_policy=0` 关不掉）。
- **今日推荐**：每一张是「名次 + 海报」：海报左边一枚大号描边数字（只描边、不填色），海报盖住数字的右缘，
  两位数（10 起）那一格放宽；海报下不再写片名（海报上印着，读屏照读「第 N 名，片名」）；两周内入库的片在海报底边居中
  挂一枚红色「最近添加」。所有设备一样。
- **片名一律中文**：卡片（首页各排、继续观看、今日推荐、搜索、资料库、年份页、文件夹页）、文件弹层、播放器与「正在播放」
  都用中文片名：总账 → 本地中文名索引 → 海报管线拿到的 TMDB 中文名，都没有才用文件名里的原名；中文名一到，卡上原位换字。
- **弱网 / 断网**：
  - 判断：Chrome / Android 读 `navigator.connection`；iOS Safari 只量纯网络的信号（图片 CDN 的下载时长、接口有没有回来）。
  - 弱网时：图片降一档、海报并发减半、预告片不挂、请求超时放宽。
  - 片库清单存了本地副本，网络 3.5 秒内没回来或断网时先用它开张，网络回来后自动换成新的；剧集表同样。
  - 后端没有总账时记 12 小时，开张不再先撞那几个 404。
  - 断网 / 恢复 / 进入省流模式时顶部有一枚提示胶囊；恢复后没加载出来的海报自动重排。
  - 播放加载画面的文案轮完还没开播时，如实提示「网络较慢，正在为您缓冲」。
- **年份页**（首页年份胶囊「查看电影和剧集」进去的那一页）：照 Apple TV「全部 … 剧集」那种列表排，一行一部 ——
  左边竖版小海报（取 w185），右边中文片名、类型（「科幻 · 冒险」）与规格徽标，最右一枚「…」；行与行之间一条发丝线，
  从文字那一列起头。电影一组、剧集一组（剧集副标题是「类型 · 全 N 集」）。点整行进详情；「…」在电影上是
  「播放 / 复制直链」，在剧集上是「继续看（或从第 1 集看起）/ 查看分集」。宽屏上排成几列，每列各是一条列表；
  iPhone Duo 折起竖拿时列表右端让出右缘的浮动导航。类型来自 TMDB 搜索结果自带的类型编号，批接口不为它多花请求。
- **返回**：年份页、文件夹页的返回钮悬浮在左上角，往下翻也在（播放时被播放器盖住）。这两种页面记了历史：
  iOS 边缘右滑、安卓返回键、浏览器后退、Esc 都回上一页。在这两种页面上开详情再关掉，仍停在原来那一页。
- **正在播放**（锁屏 / 灵动岛 / 控制中心）：中文片名、集名、海报、播放 / 暂停状态、进度，后退 / 前进 10 秒、拖动、停止；
  关掉播放器时整块撤掉，静音的预告片不会占用它。

用到的后端接口：`/api/stream-sign`（v25 起多返回一个 `hls` 字段）、`/hls/<token>/info.json`、
`/hls/<token>/master.m3u8`、`/stream/<文件名>?path=`。后端还是旧版（没有 `/hls`）时，MKV 会退回直连。

上传的页面经过了「网页另存为」类工具，有 5 行脚本被改坏，整个主脚本因此无法运行；另有两段 Cloudflare 边缘注入的
验证脚本被一起存了下来。仓库里是修好的版本（见提交记录）。

## 部署

前端（tv.cuven.us，Worker `cuven-tv`）由 Workers Builds 从仓库部署：连接 `main`，路径 `/web`，构建命令留空，部署命令
`npx wrangler deploy`。`web/wrangler.jsonc` 把这个目录当作纯静态资源上传（只传 `index.html`，配置文件与
`.wrangler/` 由 `web/.assetsignore` 排除），没有对应文件的路径都回 `index.html`。其中 `name` 必须与控制台里
这个 Worker 的名字一致。合并到 `main` 即自动上线；自定义域名在控制台里绑定，部署不会改动它。

主 Worker 照旧部署 `Stream_v25.js` 即可，不需要新的绑定。可选环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `HLS_DISABLE` | — | 设为 `1` 关闭 HLS，MKV 回到 v24 的直连方式 |
| `HLS_SEG_SEC` | `6` | 分段目标时长（2~10 秒） |
| `HLS_DV_MODE` | `auto` | `auto`：按 Apple 规范；`dvh1`：P8 改用 `dvh1` 样本入口；`off`：不发杜比信令（按 HDR10 播放，P5 除外）。主列表加 `?dv=` 可临时覆盖，方便在真机上对比 |
| `HLS_WINDOW` | `3` | 每段并行回源的切片数（1~5；加上开头直通那一路，每次调用最多 6 条连接）。高码率片源卡顿时可调大 |
| `HLS_PREFETCH` | `1` | `0` 关闭分段预取与边缘缓存、字幕借道，回到逐段现取。`*.workers.dev` 上 Cache API 不生效，自动关闭 |

建议使用 **Workers 付费计划**：一个 4K remux 分段大约消耗 20~40ms CPU，免费计划每次请求只有 10ms 上限。

### 剧集（`TV_FOLDER`，默认 `/ram2`）

前端的剧集区读这几个接口（v25 之前由旧后端提供，换到 v25 后缺了它们，剧集区整段消失 —— 现已补上）：

| 接口 | 说明 |
| --- | --- |
| `/api/tv` | 剧集表。一级目录 = 一部剧的一季；目录里再分 `Season 1 / S02 / 第三季` 的各算一季；一个目录混着几季文件时按文件里的季号拆开。目录名里读出中英文名、季、年份、分辨率、HDR / 杜比视界、编码、片源、音频、语言、平台、全 N 集 |
| `/api/tv/episodes?path=` | 分集表：按集号排（S01E02 / 1x02 / E02 / EP02 / 第2集 / 第十集 / [02] / 纯数字），样片、预告、花絮、特别篇不算，同一集留大的那个文件 |
| `/api/tmdb/season?id=&season=` | TMDB 一季的分集：中文集名、简介（中文缺的补英文）、剧照、时长 |
| `/api/tmdb?type=tv` | 只搜剧集（同名电影不会顶掉剧集的图）；剧集按「这一季的年份」也能搜到 |

TMDB 补目录名给不了的：中文名（目录只有英文名时）、这一季的首播年份（首页年份行靠它）、TMDB 编号、这一季的集数。
剧集表存在 R2（没绑就放边缘缓存），10 分钟内直接用、过期先给旧的再后台刷新，定时任务也会顺手刷新。

### 字幕清洗

所有字幕（内封、外挂、OpenSubtitles）输出成 WebVTT 前都过一遍：按行打分，删掉字幕组署名、「××发布 / 出品 / 压制」、
网址、「仅供学习交流 / 禁止商业用途 / 下载后 24 小时内删除」这类声明、QQ 群 / 公众号引流、OpenSubtitles 自己插的广告、
片源文件名；一条字幕删光了就整条不要。片头片尾各 4 分钟门槛低一档；正片中间只删几乎不可能是台词的东西，
「加入我们」「淘宝」「仅供参考」「未经授权」「corrected by the teacher」这类台词不会被误删。ASS 里 Staff / Credit 样式的整条不要，译注留着。

增强型（规则版本 c2）：
- 打分前先把全角折成半角（`ＷＷＷ．ＸＸ．ＣＯＭ` 是专门躲过滤的写法）；ASS 的矢量绘图指令（`{\p1}` 之后的 `m 0 0 l …`）、整行乱码直接删。
- 新认得的：新版 OpenSubtitles 广告（ai.OpenSubtitles、Nord VPN、浏览器插件）、`Resync for … by`、`Subtitles improved by`、
  「本资源来自」「转载请注明」「扫码关注」「更多……请访问」「机翻 / 如有错误欢迎指正」、更多字幕组名。
- 水印：整份字幕在手时（外挂、在线、直连整份），同一行在全片反复出现（≥ 3 条、前后跨 10 分钟或片长两成）、
  自己又带点署名味道（或长得像水印：括号 / 装饰符包着、带 @、像网址）就全片都删；「好的」「Thank you.」这类高频台词不受影响。
- 署名块：片头片尾一条署名被删干净了，前后 12 秒内紧挨着的「鸣谢」「感谢观看」这类弱信号一起删；
  片头片尾挂了 8 秒以上的一条（署名卡）门槛再低一档；开场旁白这类长字幕没有署名信号，留着。
- 像台词的行（你我他、语气词、问号叹号结尾、对白横杠）只靠弱信号时减一分。
- 修了一处误删：HLS 分段原来按「这一段里的前 6 / 后 6 条」认片头片尾，几乎每一段的每一条都按片头的门槛删，
  正片里「这家工作室出品的片子」这种台词会被删掉。现在分段只按时间认；外挂与在线字幕整份洗一次留在内存里，
  每段只取自己那一截（不用每段都把整份读出来重洗）。

规则版本 c3：
- SRT / VTT 里残留的 ASS 写法先收拾掉（ASS 转出来的 SRT、MKV 里的文本字幕轨常见）：`\h` → 空格、`\N` → 换行、
  `{\an8}` 这类标签去掉（顶部的仍然放顶部）、`{\p1}` 画的图形不要。原来只有 ASS 轨处理这些，SRT 里的 `\h` 原样上了屏。
- 一个字一个空格排开的汉字（「翻 译」「时 间 轴」）打分前并回去。整行只有职位、名字在下一行的署名卡
  （「翻 译 / blossomoon　大头小波……」）整条删；名字另起一条、时间一模一样的也删。
  认不出的职位（「海 报」这种排开写的小标题）挨着已经删掉的署名卡才删，台词里强调语气的「不 可 能」留着。
- 没有冒号的职位行（「翻译 张三」）只算弱信号：前后挨着的另一条也是职位行，或者后面跟了一串名字 / 英文 ID 才删；
  单独一句「后期 再说」留着。
- 新认得的广告：推广 / 商务 / 广告合作与「请联系……邮箱」、QQ 号 / 微信号、视频站账号、盗版片源站（电影天堂、YTS……）、
  博彩（「注册送彩金」）、躲过滤的网址（`www 。xx 。com`、`xx点com`）、「严禁商用 / 请勿转载」。
  台词里也会说的只算弱信号，凑到一起才删：邮箱地址、「在线观看」「免费下载」「提取码」「六合彩」「支持正版」。
- 同一条里删了署名 / 广告，剩下带署名味道的行（`@账号`、邮箱、鸣谢）不留。
- 少一处误删：行首的英文署名（`corrected by` / `encoded by` ……）只认一句话的开头，
  上一行没说完接下来的半句（「The essay was / corrected by the teacher.」，跨两条字幕也算）不再被删。

### 健康页

`/health` 除了 Dropbox / R2 / 快照，还列出可选功能是否生效：DTS / TrueHD 转码（绑没绑、在不在线）、TMDB、OpenSubtitles、

### 可选：OpenSubtitles 自动补字幕

没有简体中文字幕（或一条字幕都没有）的片子，打开详情页时在后台去 OpenSubtitles 找一条，播放时自动带上，
中文默认打开，全程不用挑。在主 Worker 上配 Secret：

| Secret | 说明 |
| --- | --- |
| `OPENSUBTITLES_API_KEY` | 必填。在 opensubtitles.com 登录后，到「API consumers」里新建一个拿到 |
| `OPENSUBTITLES_USERNAME` / `OPENSUBTITLES_PASSWORD` | 强烈建议。登录后下载配额按账号算（免费账号每天约 20 条，VIP 1000 条）；不登录就按 Workers 共享的出口 IP 算，基本拿不到 |

可选 `OPENSUBTITLES_DISABLE=1` 关闭。绑了 R2（`FILE_CACHE`）时结果长期存在 R2 里，每部片只用一次下载配额；没绑就放边缘缓存。

- **缺不缺**：已有简体（非强制字幕）就不查。只标了「中文」的那条抽一段文字认繁简：是繁体才算缺，并在播放列表里改标「繁体中文」。
- **怎么找**：先按文件哈希（命中的字幕与这个文件逐帧同步），再按 TMDB 编号（配了 `TMDB_API_KEY` 时）或片名 + 年份；剧集带季 / 集号。
- **要什么**：简体 → 简英双语 → 繁体（逐字转成简体）；一条字幕都没有的片子，没有像样的中文时才要英文。
- **怎么挑**：哈希命中 > 发布名接近 > 帧率一致 > 可信上传者 > 下载量；机翻 / AI 翻译、只翻外语部分的往后排；条数太少、时长对不上片长的跳过。帧率对不上时下载时换算。
- **对时间**：见下一节。只动在线这一条，内封与外挂字幕原样不动。
- **没找到**：7 天后再查；配额用完：等它重置；接口出错：1 小时后再查。

#### 在线字幕自动对齐

哈希不一致的在线字幕是给别的版本做的，常见三种错位：整体早 / 晚几秒（片头 logo 不同）、越往后差得越多（25 帧的 PAL 版、
24 与 23.976 帧之差）、中途一截一截地错开（加长版、电视版删掉的广告空档）。Worker 拿这个文件自己的字幕当「时间参照」，
把在线那条对上去：

- **参照**：内封字幕（时间就在 MKV 的 Cues 里，一个字节都不用多读；文字轨优先，PGS / VobSub 图形轨只有时刻也能用，
  取条数最多的那条）> 同目录外挂字幕；都没有时，用 OpenSubtitles 上与这个文件哈希一致（就是为这个文件做的）的任意语种字幕——
  为此多花一次下载配额，只在本地没有参照、选中的又不是哈希一致的时候。只取时间、不看内容，所以英文字幕也能给中文字幕当参照；
  forced 字幕（只翻外语对白的那种）不当参照。
- **算法**（与 alass / ffsubsync 同一思路，按「事件」对齐）：两边各取字幕出现 / 消失的时刻，出现只和出现比、消失只和消失比，
  两两相减投票找偏移；每个候选帧率比各投一次。再把全局投票里的几个高峰当候选偏移，逐条字幕动态规划选用哪个偏移、
  每换一次扣分——自然切成几段，切点落在两条字幕之间（平手时取空档最大处）；每段要比用相邻段的偏移明显对得更好才保留；
  最后每段在 ±0.4 秒内用 20 毫秒的格子细调。帧率比也按切段后的总分选，台阶式的错位不会被误认成帧率差。
- **核对**（宁可不改，也不能改坏）：字幕按单双条分成两半，各自独立对齐，再拿去给另一半用，对上的比例都要显著高于随机水平；
  整体上对齐后要比随机水平高 10 个百分点、比对齐前高 4 个百分点。和这部片对不上的字幕找到的「峰」是凑出来的，换一半就不灵，
  于是原样不动。
- **存法**：记录里存原始时间和对齐参数。参照以后变好了（比如记录是直连那边先建的，只有外挂可参照）会重算一次再存回去；
  HLS 字幕分段的缓存键和直连的字幕链接都带着对齐结果的指纹，换了对齐不会读到旧时间。`/info.json` 的 `online.sync`
  写着用了哪条参照、帧率比、每段偏移、对齐前后对上的比例、交叉验证的分数，排查时看这里。
- **开销**：两小时的片子约 0.1 秒 CPU，每个文件只算一次。

### 可选：DTS / TrueHD 转码 Worker（`audio-tx/`）

Workers 不允许运行时编译 WASM，所以转码器是一个单独的小 Worker（精简的 FFmpeg 6.1.1：DTS、TrueHD、MLP、
Opus、Vorbis、MP2/MP3、PCM 解码器 + AC-3 编码器 + libswresample，编成 1 MB 的 WASM，已编好放在仓库里）。
它要 Workers 付费计划（一个 6 秒分段的转码要几十到一两百毫秒 CPU）。

**开启只要两步，都在 Cloudflare 控制台里点：**

1. 部署转码 Worker（与前端 cuven-tv 同一种方式，用 Workers Builds 从仓库部署）：
   Workers 和 Pages → 创建 → 导入存储库 → 选这个仓库，然后填
   - 项目名称：`cuven-audio-tx`（必须是这个名字，与 `audio-tx/wrangler.toml` 一致）
   - 根目录：`audio-tx`
   - 构建命令：留空
   - 部署命令：`npx wrangler deploy`

   也可以在本机 `cd audio-tx && npx wrangler deploy`。
2. 把主 Worker（`stream.cuven.online` 那个）接上它，两种方式任选其一：
   - **Service Binding**：主 Worker → 设置 → 绑定 → 添加 → 服务绑定，变量名 `AUDIO_TX`，服务选 `cuven-audio-tx`。
   - **公网地址（不用绑定）**：转码 Worker 挂自定义域名（`audio-tx/wrangler.toml` 里写的是 `audio.cuven.us`，
     每次构建都会保留）。然后：
     1. 转码 Worker → 设置 → 变量和机密 → 添加，类型选「密钥（Secret）」，名称 `AUDIO_TX_KEY`，值随便一串够长的随机字符。
     2. 主 Worker → 设置 → 变量和机密：添加文本变量 `AUDIO_TX_URL` = `https://audio.cuven.us`，
        再添加密钥 `AUDIO_TX_KEY`，值和上一步**完全一样**。

     密钥是为了挡住外人：自定义域名谁都能访问，不设的话任何人都能拿它转码、耗你的 CPU。
     配了之后，不带或带错密钥的请求一律 401。

打开 `https://stream.cuven.online/health`，「DTS / TrueHD」一行显示「✅ 已绑定，转码 Worker 在线」
（公网地址时是「✅ 经 audio.cuven.us，转码 Worker 在线，密钥一致」）就生效了；两边密钥不一样时会直接写「密钥不对」。
（健康页还会列出 TMDB、OpenSubtitles、剧集目录、访问保护是否配好。）

用 wrangler 部署主 Worker、走 Service Binding 的，等价写法是在主 Worker 的 `wrangler.toml` 里加：

```toml
[[services]]
binding = "AUDIO_TX"
service = "cuven-audio-tx"
```

接上后，这些音轨会以「DTS → Dolby Digital 5.1」之类的名字出现在音轨菜单里。如果片源只有 DTS / TrueHD，
转码轨就是默认音轨。转码轨的分段落在全局 AC-3 帧网格上，跨分段时先预热、并越过分段边界多读一点，
所以接缝处不会出爆音（测试里与原声对比 SNR 76 dB 以上）。转好的分段会进边缘缓存，拖动回看时不必重新转码。
没接时，这些音轨不进播放列表，播放页会给出提示。

从源码重建 WASM：`audio-tx/build.sh`（需要 emscripten 与 FFmpeg 6.1.1 源码）。

## 限制

- 需要 MKV 的 Cues 关键帧索引（mkvmerge、MakeMKV、ffmpeg 产出的文件都有）。没有索引的文件返回 422，播放页自动回退直连。
- 不做自适应码率：始终是原始码率，4K remux 需要相应的网络带宽。
- 图形字幕（PGS / VobSub）无法转成 WebVTT，不会列出。
- 双轨式杜比视界（BL 与 EL 分在两条 MKV 轨道）按 HDR10 播放。单轨 P7（MakeMKV / mkvmerge 默认）会被正确转为 8.1。
- TrueHD Atmos 转码后是 5.1 声道床（没有开源的 Atmos 编码器）。E-AC-3 Atmos（WEB-DL）是直通的，Atmos 完整保留。

## 已验证（本地测试台：真实 Worker 代码 + 模拟 Dropbox）

- **视频直通**：HEVC 10bit HDR10（开放 GOP + B 帧金字塔）、H.264（B 帧金字塔）的每个包都与源 MKV 逐字节一致；DTS 单调且不大于 PTS，跨分段连续。
- **音频直通**：E-AC-3 / AC-3 / AAC / FLAC 逐包一致，时间轴吸附到精确的采样网格。
- **杜比视界**：P5、P8.1、P7 FEL 三种样片的信令都正确。P7 的增强层全部丢弃，RPU 全部转为 profile 8。RPU 改写逐字节对照了 dovi_tool 的测试向量：MEL/FEL→8.1 与参考输出完全一致，705 个 RPU 往返中有 704 个一致；剩下那个是测试素材本身缺少防竞争字节。
- **兼容性**：ffmpeg 作为 HLS 客户端完整解码所有渲染，帧 MD5 与源一致；Chromium MSE 接受输出的 fMP4，缓冲区连续，可播放、可跳转。
- **转码**：DTS / TrueHD / Opus → AC-3 与参考解码逐采样对齐（偏移 0），信噪比约 77 dB；分段接缝处的误差最多是中位误差的 1.3 倍（无爆音）。
- **片名匹配**（模拟 TMDB：搜索结果按热度排、错的那部排在前面）：同名不同年（《沙丘》1984 / 2021，不带年份时取票数多的那部，
  不取更热门的续集）、片名里的年份（《银翼杀手2049》《神奇女侠1984》）、续集号（《玩具总动员3》不认成 4）、中英文名都在文件名里、
  原名是韩文 / 日文（靠英文名或别名表认出）、样片不认、搜不到不拿剧集顶、没有海报时 iTunes 补一张、iTunes 的续集或别的片子不拿来顶、
  TMDB 出错那一项不回也不缓存、剧集按编号取。
- **字幕**：内封 SRT / ASS（含 zlib）、字幕没有 Cues 时的扫描兜底、外挂字幕都正确。乱序请求分段与顺序请求的输出逐字节一致。
- **OpenSubtitles**（模拟接口）：文件哈希与独立实现一致、查询参数规范（排序、小写）、登录一次后带 token；哈希命中的胜过下载量高的
  与机翻的，帧率换算；只有繁体时转成简体；GBK 字幕解码；没找到与配额用完都记下、不重复查；已有简体不查；「中文」实为繁体时改标并让在线简体默认；直连 /api/subs 带上它。
- **在线字幕对齐**：样片里内封英文字幕当参照，在线字幕整体晚 3.2 秒、PAL 加速、中途错开 6.5 秒三种都对回原位（平均差 1 毫秒以内），
  HLS 分段与直连整份都是对齐后的时间；本来对得上的、和片子对不上的原样不动；片子里没有字幕时拿同哈希的英文字幕当参照，
  只多花一次下载；PGS 只有时刻也能当参照。合成的长片（参照与在线字幕各自抖动、拆合、漏译）：45 分钟一集 5 级广告台阶、

  视频那一遍写好的 VTT（与扫描结果逐字一致）；同一段的视频与字幕同时到时也只读一遍字节。
