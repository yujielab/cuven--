# 画面光影：Cuven 原生动态反射播放器

半折的 iPhone Duo 上，播放器分成上下两块：上面是画面，下面是控制面板（参照 Netflix 在半折时的样子）。
面板上每块卡片的「面」由 Metal 实时绘制，**画面里真实的光**会映在卡片上：火光是暖的，海面是冷的，
夜景只剩局部的灯，霓虹是几种分开的颜色；光从画面的哪个位置来，就照亮哪一边的卡片。
所有代码都是原生的：SwiftUI、AVFoundation、AVKit、Metal、MetalKit、Core Video、Core Motion、UIKit。
不用 WebView，也不用 Web 渲染。

## 工程结构

## 界面：Touch Bar + 液态玻璃信息区（用户要求，参照 MacBook Touch Bar 与 Apple TV 的信息面板）

面板分两块：最上面一条 **Touch Bar**（`PlayerToolbar.swift`），下面一块液态玻璃的 **信息区**（`PlayerInfoDeck.swift`）。桌面、书本两种姿态同一个排法。

**Touch Bar**（用户要求：可滑动、点了无缝展开，集成字幕、音轨、声音、播放 / 暂停、锁定屏幕、前进、后退、进度条、亮度、全屏、小窗口）：

| 样子 | 怎么到 | 键 |
| --- | --- | --- |
| 播放那一排（默认） | — | 关闭 \| 后退 10 秒、播放 / 暂停、前进 10 秒 \| 进度条 \| ‹ + 音量、亮度、锁定（放不下就少几颗，进度条至少留 130 点） |
| 控制条 | 点「‹」或往左滑 | ⊗ \| 字幕、音轨 \| 亮度、音量 \| 小窗口、全屏、锁定屏幕（一样宽、铺满）；⊗ 或往右滑收回 |
| 亮度 / 音量滑杆 | 点一下那颗键 | ⊗ \| 整条滑杆（符号随大小变，右边是百分数）；按住那颗键左右拖：直接调，松手收回 |
| 进度条 | 点一下进度条 | ⊗ \| 整条进度条（当前时间、剩余时间）；收起时也能直接拖，松手才跳过去 |
| 字幕 / 音轨 | 点那颗键 | ⊗ \| 一排选项（选中的白底黑字，多了可以左右滑） |

- **无缝**：所有键在同一个形变组（`bar`）里。换样子时留下来的键用弹簧挪到新位置、长成新的大小（音量键长成音量滑杆），走掉的键融进留下的那些，新来的从走掉的那片里长出来；符号同时淡入淡出、播放 / 暂停和锁用 Magic Replace。
- **键面**：Metal 画的深色键（画面的光、隔着折痕映过来的画面、高光），圆角 14，组内 6 点、组间 14 点。
- **锁定屏幕**：这一页的方向锁在按下时的方向，转动设备不跟着转（`CuvenPlayerViewController.lockedOrientation`）；锁着时那颗键亮起来（白底、`lock.rotation`）。解开、点全屏、合上 / 摊平时回到原来的方向规则。
- **全屏**：退出半折的版面，回到系统播放器全屏，方向回到原来的规则（`VideoOrientation`：Duo 内屏跟着设备转）。
- **小窗口**：画中画，播放器收起回到 App（iOS 不让 App 自己回到系统主屏幕；上滑回主屏幕时会自动进小窗口）。
- **声音**：系统音量（和侧边音量键同一个），经过面板里藏着的一个 `MPVolumeView` 设；它在屏上时系统的音量提示不弹。
- 播放速度、下一集不在这一条上（用户列的功能里没有）：下一集在信息区的「简介」里。

**信息区**（参照 Apple TV：液态玻璃，「保持液态玻璃设计」）：一排胶囊标签，选中的白底黑字、其余液态玻璃；最右边一颗 ✦ 是影院光影的设置。

1. **简介**：这一集的标题、简介、「类型 · 第几季 · 第几集 · 时长」和规格徽标（4K 实心、杜比视界 / 杜比全景声 / HDR 描边）；右边玻璃胶囊「从头开始」「下一集」（剧集后面还有才有）「前往节目」（收起播放器，推进这一部的详情页）；窄的时候按钮排到下面。剧集的分集标题、简介、时长开播后从 TMDB 的这一季补上。
2. **InSight**：这一部的演员（头像、名字、角色），玻璃卡，左右滑。
3. **继续观看**：别的看到一半的（和主页那一排同一套画面和说法），点了接着放（剧集把后面几集排进队列）。
4. **推荐**：一次一部（同类型的片子，没有就用精选），大字标居中、「类型 · 年份」和评分，「＋ 想看」/「已在想看」「跳过」两颗白胶囊（参照图 7）。

没有内容的标签不出。闲置 5 秒（播放中、没在拖、Touch Bar 没展开滑杆 / 进度条 / 选项）：Touch Bar 的键和信息区一起淡出，面板上只留画面的光；碰一下就回来，这一下不会误触按钮。

摆法：

| 摆法 | 什么时候 | 画面 | 面板 | 默认折叠角度 |
| --- | --- | --- | --- | --- |
| `tabletop` | 半折，横着的折痕（桌面） | 折痕以上 | 折痕以下 | 105°，有铰链读数就用读数 |
| `book` | 半折，竖着的折痕（书本） | 右页 | 左页 | 105°，有铰链读数就用读数 |
| `stacked` | 实验室、设置页预览，竖着的屏 | 上（16:9） | 下 | 115°（模拟） |
| `sideBySide` | 实验室，横着的屏 | 右 58% | 左 | 115°（模拟） |

其余情况（摊平、合上、普通 iPhone）照旧用系统播放器（`AVPlayerViewController`）；面板上的「全屏」也回到系统播放器。

## 真机反馈后的重做（姿态、形变、无硬边、闲置、过曝）

参照 Netflix 在 iPhone Duo 上的播放器：控制随全屏、书本、桌面几种摆法重新排，始终够得着；控制上的反光跟着铰链角度变。

- **姿态**：
  - **桌面**：横着的折痕，画面在上、控制在下。
  - **书本**：竖着的折痕，一页画面、一页控制（参照 Netflix 样机改成了右页画面、左页控制，见下一节）。
  - **其余**：摊平、合上照旧用系统播放器。
  - **换姿态**：同一套卡片在渲染器里从旧位置形变到新位置。
- **无缝形变**（用户要求：所有交互控件支持无缝形变和动效）：
  - **卡片形状**：渲染器用临界阻尼弹簧（约 0.42 秒，分步积分）让每块卡片的位置、大小、圆角跟着目标走，排版变了只会形变过去，不会跳。
  - **亮起状态**：锁定时那一块的亮起是 0…1 渐变，不是开关一下。
  - **进场和离场**：卡片进场从 92% 长大、淡入；离场缩小、淡出。
  - **同组互融**：同一形变组的卡片会互相融合。第四行的工具点开亮度或音量时，六块融成一条滑杆；收起时再分开。卡片的进场离场跟着状态立刻开始，不等 SwiftUI 的淡出做完。
  - **符号**：播放 / 暂停、锁用 Magic Replace 形变；第四行与滑杆之间的符号淡入淡出加 0.96 缩放。
- **光没有硬边**（用户截图圈出的红色区域）：
  - 控制面现在是整片的：满宽，从折痕一直到屏幕底；卡片排在里面，留出安全区和 8 点边距。
  - 漏光四边羽化：两侧 40 点、靠折痕那边 56 点、底边 40 点，所以光不会在面板矩形的边上断成一条线。
- **闲置**（用户截图：玻璃没有消失）：卡片收拢、完全淡出（约 0.4 秒），面板上只留画面的环境光；这时漏光再加强 35%。碰一下，卡片从 92% 长回来，符号淡入并升回原位。
- **画面过曝**（真机反馈：半折或从后台回来后画面过曝，重新播放就正常）：
  - **单一画面层**：半折时系统播放器那一层放开播放器（`vc.player = nil`），同一时间只有面板这一层画面在显示；收起时把播放器还回去。
  - **重新接上**：画面层在播放中途接上时，原地精确 seek 一下，让解码和显示从关键帧重新走一遍。
  - **后台不摘画面**：面板这一层退到后台不再摘掉画面，由它自动进画中画。
  - ~~分析用的帧单独转 SDR~~：撤掉了，见下一条。
  - **HDR / 杜比视界的片子不取帧**（用户真机截图：半折时杜比视界的片子整片发绿、人物发品红——杜比视界 5 没经过杜比视界处理时的样子，
    面板上的光也是绿的，说明是解码那一路变了）：在播放的片源上挂取帧的输出（`AVPlayerItemVideoOutput`）会改变屏上的画面——
    不指定颜色时过曝，指定 SDR Rec. 709 时变绿。所以现在只有确认是 SDR 的片源才挂：
    - **怎么知道**：服务器的 `info.json`（`range` 是 PQ / HLG、或带杜比视界档位 → HDR；SDR → SDR）、文件名（「杜比视界」「HDR」）、
      片源自己（本机文件看视频轨的格式：PQ / HLG 传递函数、`dvh1` / `dvhe` / `dva1` / `dvav`；HLS 看各档的 `VIDEO-RANGE`，
      开播以后再看播放器轨道的格式）。认出来之前不挂；后来才认出是 HDR 的，立刻摘掉。
    - **这时光影读什么**：这一集的剧照（缩到 256 × 144，走同一套分析，喂约 3 秒让平滑收敛，然后就停在那儿）。卡片上仍是这一部的颜色，只是不跟着画面变。
  - 这几条是按现象推断的修法，还要在真机上确认。

## 参照 Netflix / Mux 的重做（用户要求「完全重做参考」；面板后来又按用户要求换成了上面那条 Touch Bar + 信息区，下面这节的「方块格子」「转成四列」已不再用，光影部分照旧）

参照的两篇：Netflix 的「a mobile experience that moves with you」（附带的 Makers 视频里有 iPhone Duo 播放器的样机和模拟器画面），
Mux 的「What the iPhone Duo means for web development」（用 Video.js 在网页上复刻了同一个界面）。从里面取的：

- **控制跟着姿态动**（Netflix：「adapting seamlessly no matter how you're watching — full screen, book pose, tent pose or
  tabletop — so they stay within reach」）：
  - 卡片的位置由 `PlayerPanelGrid` 在「沿折痕、离折痕」两个方向上算一次，再按折痕在面板的哪一边换到屏上。
  - **桌面**：四行，第一行贴着折痕。
  - **书本**：同一套方块转 90° 成四列，离折痕最近的一列是关闭 / 信息卡 / 画中画 / 锁定；沿折痕从上往下就是桌面时从左往右的顺序。
    跟 Netflix 样机一样左页控制、右页画面。信息卡竖排（字标、片名、集数从上往下），进度条竖着走（从上往下播，当前时间在上、总时长在下），
    亮度 / 音量那一条也竖过来（往上是大，滑杆在 UIKit 里转 90°，拖动跟着转）。
  - **换姿态**：每一块从旧位置形变到新位置（卡面由渲染器的弹簧带过去，符号和字由 SwiftUI 的弹簧带过去；信息卡、进度条换排法用 `AnyLayout`，字跟着滑过去）。
  - **全屏**：回到系统播放器。**帐篷姿态**：向内折的屏立成帐篷时内屏朝外看不到，这一种不做。
- **方块，不是圆**：参照图（模拟器和真机都是）第二排是三块一样大的圆角方块，所以后退 / 播放 / 前进改回方块，播放那块的强调最高（反射最强）。
- **画面映在面板上**（Netflix：「a subtle, reflective glow to the controls that responds to the angle of the hinge」；
  Mux 的做法：把画面上下翻过来、模糊、离折痕越远越淡，垫在控制后面）：
  - 投影那一步（`cuven_projectIrradiance`）里，面板上离折痕 d 的一点看回去，取画面里离它近边 d·k 的那一点——画面的下沿贴着折痕，天空在更远处，像一面镜子。
  - 贴着折痕的地方取清楚一点的光图，越远越取模糊的（光泽面的反射），离折痕越远越淡，超出画面两边的地方渐渐没了。
  - **跟着铰链角度变**：立到 90° 左右镜像是 1 : 1、最亮；往平里打开，映像往折痕那边收（k 变大）、变淡；合得比 90° 还小，映像往外伸一点。
  - 强度跟着模式的反射（标准不开；影院约 0.4；沉浸约 0.68），方块上亮、方块之间的黑底上只剩约五分之一（漏光），都是同一张图，所以没有硬边。
  - 原来的「弥散光」（取画面在旁边那一段的几种深度平均）由这个代替：同样是画面自己的颜色、同样柔和，但有了上下的结构。

## 影院光影（Cinematic Reflection Mode）

三种模式可以随时切换，正在放的时候也可以。

| | 标准 | 影院（默认） | 沉浸 |
| --- | --- | --- | --- |
| 视频分析 | 不做（Core Motion 也不开） | 24 次/秒，闲置 12 | 30 次/秒，闲置 15 |
| 取样尺寸 | — | 256×144 | 384×216 |
| 投影网格 | — | 16×9 | 32×18 |
| 光源 | — | 2 个 | 4 个 |
| 环境光 / 镜面反射 / 高光 / 边缘光 | 0 | 1.0 / 0.45 / 0.65 / 0.8 | 1.15 / 0.75 / 1.0 / 1.0 |
| 反射柔化 | — | 0.6 | 0.35（更清楚） |
| 两层高光 | — | 无 | 有（亮点外再加一层宽光泽） |
| 面板漏光 | — | 0.22 | 0.4 |
| 空间响应 | 无 | 一半 | 完整 |

- **同一条管线**：三种模式共用同一条渲染管线，只是参数不同。
  - 参数由 `LightingProfile` 给出。`CinematicReflectionMode` = 模式 + 五个微调 + 三个开关，按当前档位解析成 profile。
  - 渲染器把着色器拿到的参数（`look` / `look2`）朝新的 profile 缓动，约 0.6 秒到位。所以切换模式是平滑过渡，不会跳变。
  - 切到「标准」时光先淡出，然后分析完全停下。
- **微调**（设置面板）：
  - 反射强度：0–150%，乘在总强度上。
  - 环境光：0–150%，同时影响漫反射和面板漏光。
  - 镜面高光、边缘光：0–150%。
  - 反射柔化：0–200%，乘在模式的柔化值上。
  - 「恢复默认」只回到当前模式的设计值，模式本身和开关不动。
- **开关**：
  - 空间响应：设备姿态，以及有读数时的铰链角度，会移动反射和高光。
  - 自适应光影：见下面的档位。
  - 预览光影：设置页里用测试画面实时预览。
- **面板漏光**：卡片之间的黑底上有一层从画面那边漏下来的光。它跟着辐照度走（颜色、位置都随画面），离铰链越远越淡，所以面板不会整片发光。
- **闲置**（5 秒没碰）：
  - 符号淡出并往下沉 6 点；卡片完全淡出。
  - 环境光照常，高光降到 40%，镜面反射降到 65%；取样频率和刷新率减半（30 fps）。
  - 碰一下面板，符号用弹簧动画淡入并升回原位，高光回来。这一下只叫回控制，不触发按钮。
  - 光影设置弹窗开着、拖进度条、锁定、展开滑杆时不进闲置。
- **设置存在哪里**：本机 `UserDefaults`（`cinematic_reflection_mode_v1`、`cinematic_preview_lighting`）。以前的「画面光影」开关如果是关着的，迁移成「标准」；以前的强度换算成反射强度。
- **入口**：
  - 播放时点剧集信息卡，弹出精简版设置，下面的面板就是预览。
  - 账户与设置 → 播放 →「影院光影」打开完整版（多一块测试画面的实时预览）。
  - 光影实验室里也有同一块设置，外加开发者诊断。

### 自适应档位（`AdaptiveLightingController`）

每秒检查一次，按顺序取第一条命中的：

1. 在后台：暂停。
2. 过热（critical）：冻结在最后一帧。这一条不管「自适应光影」开没开都会生效。
3. 「自适应光影」关着，或模式是「标准」：完整档。
4. 下面任一条命中就降档：偏热（serious）；低电量模式；没插电且电量低于 20%；沉浸模式但 GPU 早于 Apple 7（A14 之前）；片源宽于 4K 且 GPU 早于 Apple 9；光影的 GPU 用时连续 3 次超过 5 ms（回落到 2.5 ms 以下再恢复，带滞后，不会来回跳）。

降档的做法：取样频率减半、尺寸降到 256×144、网格降到 16×9、去掉第二层高光、刷新率 30 fps。样子还在，只是细节少一些。
光影分析在 GPU 上和视频解码并行，播放从不等光影，光影也从不等播放。

### 开发者诊断（光影实验室）

- **模式**：当前模式、是否闲置。
- **刷新**：实际 / 目标视频取样频率、画面帧率。
- **耗时**：GPU 用时、CPU 编码用时。
- **档位**：当前档位、降档原因、GPU 等级、热状态。
- **光影数值**：生效中的反射强度、混合和高光；空间响应的倾斜 x / y 与强度系数；折叠角度（标明是否来自铰链）。
- **资源**：纹理占用、进程内存、跳过的帧。
- **取样**：主色（平均色 + 各光源的颜色和位置）、16×9 取样网格、追踪到的光源圈。

## 界面细节（影院光影这一版）

- **剧集信息卡**：小号的 Cuven 字标（和登录页、加载画面同一套圆体）+ 片名 + 第几集 + 一个淡淡的「›」。点开是光影设置。
- **第二行**：后退 / 播放 / 前进换成三颗圆的。中间那颗最大（最多 132 点）、反射最强（emphasis 1），两边是它的 74%。
- **进度条**：细（3 点），已播放部分是 Cuven 蓝，剩余部分是中性灰；左边当前时间、右边总时长。播放时每 0.25 秒更新一次，中间线性补平，看起来连续在走。拖动时圆点从 14 点放大到 22 点，松手才 seek。
- **按钮按下**：符号和卡面一起缩到 0.97，卡面略亮；用弹簧动画，没有夸张的回弹。

## 渲染管线

```
AVPlayer ──► AVPlayerLayer（画面本身：硬件解码、HDR、画中画，全是系统的）
   │
   └─► AVPlayerItemVideoOutput（256×144 BGRA、IOSurface、Metal 兼容）
          │ CVMetalTextureCache（零拷贝，没有 CPU 读）
          ▼
  ① cuven_sampleVideo       → 光照图 64×36 RGBA16F（线性光，亮的地方权重最高 7 倍，保住局部光源）
  ② cuven_analyzeScene      → 16×9 分区颜色、整帧平均、峰值亮度、亮区覆盖、转场值（和上一帧比）
  ③ cuven_temporalBlend     → 平滑后的光照图（双缓冲；τ 平时 0.10 s，转场时 0.38 s）
  ④ cuven_gaussianBlur ×4   → near（σ≈1.5）、far（σ≈4.5）
  ⑤ cuven_selectLights      → 最多 4 个光源：位置、颜色、半径、亮度；跨帧匹配、淡入淡出
  ⑥ cuven_projectIrradiance → 面板 ¼ 分辨率的辐照度（画面折起来当面光源积分）
  ⑦ 卡片材质（全分辨率）    → 漫反射 + 菲涅耳镜面反射 + 边缘光 + 可读性上限
  ⑧ 高光（½ 分辨率，叠加）  → 4 个光源的 Blinn–Phong
  ⑨ 合成（全分辨率）        → 卡面 + 高光（5 点 tent 上采样）→ sRGB → 抖动 → 屏幕
```

①～⑥ 每 1/30 秒跑一次，前提是视频有新帧。⑦～⑨ 跟显示刷新率走（60 Hz），没有变化的帧整帧跳过。
全部编码在同一个命令缓冲里，GPU 按顺序执行，中间结果不回 CPU。
唯一的 CPU 读取是实验室的取样颜色：一个 2.3 KB 的共享缓冲，每秒最多读 4 次。

### 光照模型（`LightingShaderTypes.h`）

- **铰链空间**：x 沿铰链；y 从铰链指向面板（也就是朝着观看的人）；z 垂直于面板向上。面板是 z = 0 平面。画面那一半以折叠角 φ 从铰链立起来：φ = 180° 是摊平，90° 是竖直，像笔记本屏幕。
- **画面上一点**：距铰链 h，沿铰链 s，三维位置 Q = (s, h·cos φ, h·sin φ + spill)。spill（46 点）模拟屏幕边缘漏出来的光，让摊平的版面也有一点光。
- **屏幕正面法线**：n = (0, sin φ, −cos φ)。

- **漫反射**：把画面看成 32×18 个面光源。面板上每个 ¼ 分辨率的点 P 收到的辐照度是

  E = Σ L · (0.3 + 0.7·max(0, cos θs)) · max(0, cos θp) / (d² + 30²) · ΔA / π · 3.2

  其中 cos θs = n·(P−Q)/d，是屏幕向 P 发光的角度；cos θp = (Q.z − P.z)/d，是面板接收光的角度。距离按平方衰减，所以离铰链近的卡更亮，左边的光照亮左边的卡。多个光源、各自的颜色和位置都在同一个求和里，没有任何「平均颜色」。
- **弥散光**（用户要求：控制区应该是弥散光，而不只是边缘的细光）：在上面的物理辐照度之外，面板上每一点都取画面里正对着它的那一列颜色。
  - **取样**：取 3 个深度（靠近铰链的画面边缘、画面三成处、六成五处），权重 0.5 / 0.32 / 0.18，都从宽模糊的 far 图上取。
  - **扩散**：从离画面最近的那条边铺开，按面板深度的 0.6 做指数衰减；超出画面左右两侧的部分按 140 点衰减，不会把边缘颜色抹过去。
  - **效果**：卡面和卡片之间的黑底都被画面自己的颜色柔和地照着。海面是一片青色，夜景三盏路灯留下三团暖光，霓虹左边品红、右边青色，不会整片均匀发光。
  - **为什么需要它**：物理辐照度把整幅画面积分在一起，颜色偏灰；弥散光保住了局部的颜色。
  - **背景漏光**：影院 0.3、沉浸 0.5，同样随画面和距离变化。
- **镜面反射**：
  1. 视线 V 从眼睛到卡面上的点，按卡片法线 N 反射成 R。N 在中间是平的，靠边缘 9 点的倒角里向外翻，整面还带一点微拱。
  2. R 与折起来的屏幕平面求交，得到它「看到」画面的哪个位置，在那里取样光照图：距离越远越糊，从 near 过渡到 far。
  3. 乘上菲涅耳系数 F = 0.06 + 0.94·(1 − N·V)⁵、反射强度和卡片的光泽度。
  4. 交点落在画面外就渐隐。
  5. 摊平时射线碰不到屏幕，镜面反射自然消失。
- **高光**：对 ⑤ 找到的每个光源算归一化 Blinn–Phong：(n+8)/(8π)·(N·H)ⁿ。光源越小 n 越大：小灯是一个亮点，大片亮窗是一层宽光泽。再乘屏幕朝 P 的发光量和 1/(1 + d²/700²) 衰减。
- **边缘光**：卡片边缘内侧 2 点的一条细带，接收「漫反射 × 1.8 + 镜面 × 1.2」；朝向屏幕的那条边最亮。
- **可读性**：暗卡片受光后的亮度用软上限压在线性 0.12 以内，高光另压在 0.06 以内，合起来约等于 sRGB 0.46。白色符号对卡面的对比度因此至少 4.6 : 1（WCAG AA）。亮着的卡（锁定）不压。
- **眼睛位置**：面板正前方 520 点、高 620 点。Core Motion 测到的倾斜会把眼睛左右挪最多 260 点、前后 160 点、上下 220 点，反射和高光随设备转动在卡上移动。

### 时间与转场

- `cuven_analyzeScene` 在开方空间里比较每个分区和上一帧的颜色，这样两个暗场之间的切换也能测到。比较结果映射成 0～1 的转场值。
- 时间平滑的 τ = mix(0.10 s, 0.38 s, 转场值)：同一个镜头里光跟得紧（火光会闪），换镜头时用约 0.4 秒交叉淡化，不会一下跳过去。
- 光源每个槽位跨帧匹配到最近的新光源，以 τ = 0.25 s 靠过去；没匹配上的淡出，新出现的淡入。
- 换片源（下一集、换本机视频、循环）时整个分析清零，新片源的光从黑里淡入。
- 光影开关是约 0.4 秒的交叉淡化。按下用 τ = 0.06 s 的弹簧，闲置变暗用 τ = 0.15 s。折叠角是约 0.3 秒的临界阻尼弹簧，姿态倾斜用 τ = 0.18 s。

## 与 AVPlayer 的接入

- 画面由 `AVPlayerLayer` 画，光影另外从同一个 `AVPlayer` 取帧，两者互不影响。
- **取帧**（`VideoFrameProcessor`）：每个 `AVPlayerItem` 挂一个 `AVPlayerItemVideoOutput`。每个渲染帧检查 `player.currentItem` 换没换，所以换集、循环、换片源都会自动重新挂。
- **只取需要的帧**：每次只在 `hasNewPixelBuffer(forItemTime:)` 为真时取一帧。暂停、缓冲时什么都不取，卡上留着最后的光。
- **帧尺寸**：解码器的缩放器直接给出 256×144 的帧，没有全分辨率的 CPU 拷贝。`CVMetalTexture` 一直保留到读它的命令缓冲完成为止。
- **几何**：画面按 `presentationSize` 等比放进画面区（`AVMakeRect`），黑边不发光。
- **半折播放器**：系统播放器（`AVPlayerViewController`）照常放；半折时上面盖一层 SwiftUI，关掉系统控件，换成这里的面板。
  - 进度、音轨与字幕的首选项、自动下一集、流量统计，仍由 `PlayerCoordinator` 管。
  - 面板的画中画走 `PlayerCoordinator.panelPictureInPicture*`。

## 性能

| 项目 | 做法 |
| --- | --- |
| 界面 | 60 fps；SwiftUI 不按帧刷新。卡片位置只在排版变了时上报，诊断每秒 2 次，取样颜色每秒最多 4 次 |
| 光影更新 | 30 次/秒（热或低电量模式 15 次，过热冻结在最后一帧） |
| 分辨率 | 分析 64×36；辐照度为面板的 ¼；高光 ½；只有卡片材质和合成是全分辨率 |
| CPU↔GPU 同步 | 最多 3 帧在途；GPU 跟不上就跳过这一帧，不在主线程等 |
| 资源复用 | 管线一次建好；纹理池按尺寸 / 格式 / 用途复用；uniforms 与卡片走 `setBytes`；每帧不分配 Metal 资源 |
| 帧跳过 | 没有新视频帧、没有动画、姿态没变时整帧不画 |
| 档位 | `thermalState` 与低电量模式每秒检查一次：high（30 次 / 60 fps / 32×18）→ reduced（15 / 30 / 16×9）→ minimal（冻结 / 30） |
| 生命周期 | 进后台立即停（后台不允许跑 GPU），清掉纹理缓存和空闲纹理，停 Core Motion；回前台恢复；内存警告时清缓存 |
| 诊断 | 实验室显示画面帧率、光影更新率、GPU 时间（`gpuStartTime` / `gpuEndTime`）、CPU 编码时间、档位、热状态、纹理占用、进程内存（`phys_footprint`）、跳过的帧、折叠角度 |

纹理占用：光照图 6 张 64×36 RGBA16F，约 110 KB；辐照度约 170×90 RGBA16F，约 120 KB；全分辨率卡面 + ½ 高光 RGBA16F，669×350 点 @3× 时约 17 MB。

## 设备限制

- **折痕位置**：用 iOS 27.1 的 `GeometryProxy.reservedRegions(kind: .division)`，更早的系统不会进入半折版面。
- **铰链角度**：用 iOS 27.1 SwiftUI 的 `onHingeChange`（`DeviceHinge.angle`），只在系统报告铰链的设备上才有。
  - 引擎**不假设**任何设备都能读到铰链角度：`SpatialResponseEngine` 的折叠角来源依次是模拟值、`updateHardwareFold(_:)` 喂进来的读数、版面默认值。
  - 实验室可以开「模拟铰链角度」。
- **模拟器**：折不了，铰链没有读数，Core Motion 没有数据，空间响应在模拟器里不动。
  - UI 测试用 `-CuvenTabletop YES` 弹一个折痕固定在正中的演示页。
  - 用 `-CuvenPlayerLab YES` 打开实验室放测试画面。
- **HDR / 杜比视界**：光影取的是 8 位 BGRA，系统已映射到 SDR。画面本身照常 HDR。
- **画中画**：面板按钮启动的是面板那一层画面的画中画。系统播放器那一层的画中画（例如退到后台时自动开始）照旧由系统处理。
- **没有 Metal、或着色器建不起来**：面板退回 SwiftUI 画的深灰卡片，功能不变。实验室的「性能」里会写出原因。
- **只用 BGRA 8 位**：10 位源会先被转成 8 位再分析，对光影足够。

## 构建与运行

工程由 XcodeGen 生成：

```sh
brew install xcodegen
cd ios && xcodegen generate && open Cuven.xcodeproj
```

- **构建**：选 `Cuven` scheme，用 Xcode 27.1 以上（iOS 27.1 SDK）构建。
  - `CuvenLighting` 是 App 的依赖，会一起编译并嵌入 `Cuven.app/Frameworks/`。
  - 它的着色器编进框架自己的 `default.metallib`，运行时用 `makeDefaultLibrary(bundle:)` 加载。
- **着色器校验**：编译期由 Metal 编译器检查。运行时 `MetalShaderLibrary` 一开始就建好全部 9 条管线，有失败会记日志（`us.cuven.tv` / `lighting`），实验室里也会显示。
- **CI**：
  - `ios.yml` 编 Release IPA，并把 IPA 推到 `refs/ci/ios-ipa/<分支>`。
  - `ios-preview.yml` 在 iPhone Duo 与 iPad mini 模拟器上跑 UI 测试。实验室的截图是 `duo-39*` / `duo-49*`：测试画面四段各一张，外加一张横屏。
- **在手机上看**：
  - 半折播放：在 iPhone Duo 上放任意一部片子，展开竖拿再半折立起来。
  - 光影实验室：账户与设置 → 播放 → 光影实验室。选相册或文件里的视频，或者放「测试画面」，里面的「火光 / 海面 / 夜色 / 霓虹」可以直接跳到对应场景。
  - 关掉光影：账户与设置 → 播放 →「画面光影」。
