# 光学配对快速登录（Cuven 粒子码 CPC，规范第 2 版）

要登录的设备（网页版、或者 iPhone 的登录页）显示一团蓝色粒子云；已经登录的 iPhone 扫一下、面容 ID 确认，那台设备就登进同一个账户。
外观是照 Apple 配对动画复刻的 3D 粒子云（`web/pair.js`、iOS `PairCloud.swift`，同一套着色器）。
Apple 的协议拿不到、也不该照搬，所以**编码、解码、协议全是自己的**：码藏在每个粒子的光学深度里（屏幕上的位置决定乘多少），
3D 的云在滚、码钉在屏幕平面上；相机几帧一平均，滚动的结构抹平、码显出来，再用一个小卷积网络（GPU）还原。

```
要登录的设备                         check.cuven.us                      已登录的 iPhone
  POST /pair/open ───────────────▶ 开一团（2 分钟）：id、secret（不再有 6 位数字）
  画粒子云（id + secret）
  POST /pair/wait（长轮询 ≤ 20 秒）◀─┐                                   相机扫到云 → (id, secret)
                                    │ ◀───────────────── POST /pair/peek（带设备令牌）
                                    │                     回：哪台设备、哪里、什么时候、离你近不近 → 确认卡片
                                    │                                     面容 ID
                                    │ ◀───────────────── POST /pair/approve
  回：用户名 + 身份码（iOS 另要一枚设备令牌） ◀──┘           登录提醒邮件（方式「光学配对」）
```

## 三处同一份规范

## 编码（CPC v1）

- **64 位**：配对编号 24 位 + 密钥 32 位 + CRC-8（多项式 0x07）。
- **卷积码** K = 7，生成多项式 171 / 133（八进制），码率 1/2，补 6 个 0 → 140 码位；交织 `k → (k·53) mod 140`。
- **160 个格子**排在 5 圈上（14 / 22 / 30 / 42 / 52 个，各圈错开一点角度），其中 20 个是导频（`i mod 8 = 3`，LFSR 定的正负）——解码时用来找旋转。
  每个格子的位置按编号做一点确定的抖动（不像整齐的表格）。
- **场**：`D(x) = Σ bᵢ·Gᵢ(warp(x))`，每个格子一团 ± 高斯（径向 σ 0.070、切向 σ 是格距的 0.45），先过一个固定的正弦扭曲（丝是弯的，不是一圈圈的环）。
- **调制**：`M = （1 + 0.25·tanh(D/0.30)）×（1 + 0.6·覆盖度²·exp(−(D/0.10)²)）`——正的一侧浓一点（读得出正负），零线上浓一些。
  显示时算成 192² 的网格、存成 8 位纹理（`M / 3`），每个粒子按它在屏幕上的位置取 M，乘到光学深度上。

## 显示（GPU）

- **云本身**（和码无关）：3D 球壳 5.3 万点 + 光晕 1.65 万点 + 12 缕丝各 1500 点（固定的随机数种子，网页和 iOS 粒子一模一样），
  绕斜轴滚动、上下几圈滚得不一样快，几层剪切把壳「折」起来，带一点透视；10 秒一个循环，浓淡（gathering）照录屏拟合。
  `pair-density.png` 是按录屏拟合的逐帧光学密度校正（120 帧，每帧 112²，拼成 1368 × 1140 一张），片元着色器里两帧插值、调每个粒子的光学增益。
  所有运动都在顶点着色器里算，粒子缓冲是静态的。
- **码**：每个粒子的不透明度 `1 − (1 − a)^(增益·M)`，即光学深度 × M。码平面是屏幕平面（y 朝下，和相机拍屏幕的行号同一手性，反过来是镜像、解不出来），
  每秒转 0.05 弧度。眼睛看是云的浓淡有点起伏；相机几帧一平均，滚动的结构就抹平了。
- 画在透明底上（输出预乘：颜色 over 混合、透明度累积），浅色深色页面都对。iOS 用 Metal（`pair_cloud_vertex` / `pair_cloud_fragment`），网页用 WebGL 1。

## 解码（扫描端）

1. 相机 1920×1080 BGRA → GPU 裁正中间的正方形、缩成 256²，算「蓝色程度」`clamp((B − R)·1.6)`（白底黑底都适用）。
   相机：优先多摄的虚拟设备（贴得太近时自动换超广角微距），连续对焦限定近距离；开 `isMultitaskingCameraAccessEnabled`
   （iPhone Duo 展开、iPad 分屏 / 多窗口时不开，系统会把相机暂停，扫描框里就是空的）；被暂停、出错时圆圈下面写明原因。
2. **找框**（v1.1）：减背景（20% 分位 + 0.04）算矩得粗椭圆；24 条射线找亮边的半高点（亚像素）；最小二乘拟合中心 + 2×2 映射，去掉最差 4 个点再拟合；
   除以 `edgeK`（半高处 / 真半径）；最后用极分解去掉映射里的旋转——角度 0 永远对着画面的 x 方向，前后几帧对齐，才能取平均。
3. 极坐标展开 24 × 192（半径 0.10–1.08），每张自己归一，加一个「半径」通道。
4. **网络**（`PairNet`，约 3.2 万参数）：7 层 3×3 空洞卷积（角向首尾相接、径向补 0）+ ReLU，1×1 + tanh，输出每个点的 `tanh(D/0.35)`。在 Metal 上逐层跑，没有 Metal 时退回 CPU。
5. **最近 8 帧的极坐标图取平均**再进网络（框已经去掉旋转，手机拿稳时前后几帧对齐；云在滚，平均一下滚动的结构抹平、码留下来）；
   网络输出后，对所有 192 个旋转一起做**最小二乘解卷**（格子模板的 Gram 矩阵 + 0.001 的正则，先求逆）得到 160 个格子的软值。
6. 导频相关度最高的 3 个旋转依次试 Viterbi → CRC；同一个结果出现两次才算数。

## 训练

```
cd pairing/frames                         # 先渲染训练用的背景（要 Playwright + Chromium）
node render.mjs frames "{\"times\":$(python3 -c 'print([i*10/360 for i in range(360)])')}"
python3 convert.py frames                 # → look-frames.npz
cd ../py
python3 train.py 4000                     # 从头练（CPU 就够：约 0.5 秒一步）
SEV0=0.4 python3 train.py 4000 ../model/cpc1.pt   # 接着练（SEV0：起始难度）
python3 eval.py ../model/cpc1.pt 40 ../frames/test/*   # 合成画面的解码率 + 浏览器真渲染的带码帧
```

训练数据：渲染好的云（码关掉）每帧存覆盖度 c 和每单位覆盖度的蓝色程度 k；随机码的 M 和显示时一样算（192²、8 位、双线性、任意转角），
带码的蓝色程度 = `(1 − (1 − c)^M)·k`（光学深度 × M 时透过率 T 变成 T^M，和着色器严格一致）；连着 1–8 帧平均；
再模拟相机（透视 / 倾斜 ≤ 40°、失焦、手抖、曝光、伽马、摩尔纹、反光、噪点）→ 找框 → 极坐标；目标是真位置上的 `tanh(D/0.35)`。
找框的两个标定常数（`kRms`、`edgeK`）也在这团云上现量。

## 后端（check.cuven.us）

协议第 2 版（2026-11，「优化光学配对的速度和安全性」：先审计、再逐条改，已经部署；对已经发出去的 App 向下兼容）。

| 接口 | 谁调 | 说明 |
| --- | --- | --- |
| `POST /pair/open {device?, want_device?}` | 要登录的设备 | 开一团：`{id, secret, poll, code: "", ttl: 120, exp}`（`code` 留着空串：老版 iOS 当必填字段解）。编号 1…0xFFFFFF、密钥非 0；同一 IP（v6 按 /64）每分钟最多 12 次。记下开云那一端的国家 / ASN / 网络运营方（只给 peek 比远近，不外传） |
| `POST /pair/wait {id, poll, wait?, device?}` | 要登录的设备 | 长轮询 ≤ 20 秒：`open`（带 `exp` 和 `peeked`：有人扫到了没有）/ `approved` / `expired` / `cancelled` / `done`。有人扫到以后每 250 毫秒看一次（不然 900 毫秒），批准到登录通常在半秒内。批准后回用户名、邮箱、身份码（`c1.…`）；设备令牌**只在要的时候给**（`want_device` / `device: true`，只有 iOS 要），到期不超过批准它的那枚令牌。回包丢了：30 秒内同一个轮询令牌再问一次照样给 |
| `POST /pair/cancel {id, poll}` | 要登录的设备 | 关掉 |
| `POST /pair/peek {id, secret, device, username?, caps?}` | 扫描端 | 先看是哪台设备：设备、位置、时间，外加 `near: {level, org, country}`（`same_network` 同一网段或同一 ASN / `same_country` / `foreign` / `unknown`）和开了多久；不回完整 IP。扫到了就把这一团的有效期延到「现在 + 60 秒」（最多开云后 4 分钟），确认卡片上的人不会被过期打断 |
| `POST /pair/approve {id, secret, device, username?, caps?, ack?}` | 扫描端 | 面容 ID 之后批准。新版 App 带 `caps: ['near']`：开云那一端在别的国家 / 地区时要 `ack: 'far'`（App 里多点一次「它就在我面前」），不然 409 `far`；老版不带 `caps` 照旧。登录提醒邮件在批准真的写进去以后才发 |
| `POST /device/revoke-all {code}` | 已登录的设备 | 让这个账户所有已发出的设备令牌失效（要一枚有效的身份码） |

- **状态**存在 R2（强一致）`pair/<id>.json`。每一次状态变化（试错计数、批准、交出、过期、取消、延期）都是带 ETag 的条件写，并发的请求不会互相覆盖：试错的次数数得准，批准和取消不会同时成立。
- **不存在的编号和错的密钥回一样的** 404 `not_found`（「没认清，再扫一次」）：扫描端当作没认清、接着扫，不报错；猜编号也看不出哪个存在。错 8 次这一团作废。
- **6 位数字那条路关了**：只带 `code` 的请求回 410 `gone`（「请更新 App，现在只能扫描粒子云」）。以前它不记试错次数，拿自己的设备令牌就能一直猜，等于把 56 位降到 20 位。
- **来源限制**：浏览器发来的 `/pair/*`（带 `Origin`）只认 `PAIR_ORIGINS`（默认 `https://tv.cuven.us`），别的网站 403 —— 钓鱼页没法在受害者自己的浏览器里开一团云、把令牌转走。App 不带 `Origin`，不受影响。
- **设备令牌** `d1.<用户名>.<设备号>.<到期>.<签名>`（HMAC，180 天）：密码 / 邮箱验证码登录时带 `device: true` 领，iOS 存钥匙串，只在扫描端用。
  - 只认它自己的账户（扫描端带上现在登录的是谁，对不上 409 `device_mismatch`）。
  - 能**真正吊销**：每个账户一个「此前签发的作废」时间（R2 私有对象 `devnb/<用户名>.json`），改密码、改名（旧名）、账户重建、`/device/revoke-all` 时设成现在。
  - 不会自己续命：配对发的令牌到期不超过批准它的那一枚；拿身份码换令牌的 `/device` 已停用（410）。
  - 网页版和 Windows 版不要也不存（网页开机和退出时把旧的 `cuven_pair_device` 删掉；Windows 开机删掉 `device.bin`）。
- **限流**：每枚设备令牌、每个账户、每个 IP 段各有上限（10 分钟 20 / 30 / 60 次），计数写不进去（KV 限流）也不会变成 500。
- **收尾**：交出去的那一刻抹掉密钥、完整 IP 和网络信息；取消、过期、作废时整条抹掉，只留编号、状态和时间。建议给 `pair/` 前缀配一条 R2 生命周期规则（1 天后删除）。
- **快**：开云、扫到、批准各自的存储读写并行；显示端在码快过期（还没人扫到）时提前换一团，不会把一团死码留在屏幕上；码纹理用稀疏基预先算好（`setCode` 从上百毫秒降到几毫秒，输出逐字节不变）；
  iOS 扫描端用广角镜头（以前多摄设备默认落在超广角上，云在画面里太小）、两次之间相机不停、解码器在后台建好、每帧不再重新分配缓冲。

## 入口

- 网页版登录框：一打开就是粒子云（浏览器画不了、带着重设授权、或者调用方要密码时除外），下面「使用账户密码登录」切到密码页；批准后自动登录（不存设备令牌）。标签页切到后台时这一团先收起，回来再开新的。
- iOS 登录页：一出来先显示粒子云（演示模式除外），下面「使用账户密码登录」回到登录页；登录页上「用 iPhone 扫描登录」可以再打开。
- iOS 主页右上角头像左边的「光学扫描」→ 相机 → 确认卡片（同一网络时一行绿字；开云那一端在别的国家 / 地区时一条红色提示，要多点一次）→ 面容 ID → 批准。没设设备密码的手机不能批准。账户页的登录方式显示「光学配对」。
- 自检：Debug 构建带 `-CuvenPairLab YES` 启动打开自检页（编码对照测试向量、Viterbi、离屏 Metal 画一团云再用 GPU 网络解出来）；
  `DuoUnfoldedTests.testPairLab` 在 iPad 模拟器上跑一遍，截图 `duo-4s-pair-lab`。

## 现在验证到哪一步

- **浏览器真渲染的带码云**（`web/pair.js` 原样，600² 画布、正对，当成相机画面，`eval.py` 的第二部分）：6 个随机码、每个连着 40 帧，
  按扫描端的做法每帧取最近 16 帧平均：6 个码全都解得出来，窗口成功率 134 / 150（89%）；单帧几乎解不出（11 / 240）——码比云自己滚动的结构弱，要靠平均。
- **合成相机画面**（同一套云 × 随机码，再加透视、失焦、曝光、噪点、摩尔纹、反光；60 个随机码）：

  | 相机条件（训练用的难度） | 单帧 | 16 帧平均 |
  | --- | --- | --- |
  | 0.5（正常拿着对准） | 35% | 50% |
  | 0.75（斜一些、糊一些） | 17% | 33% |
  | 1.0（斜 40°、失焦、手抖、反光都拉满） | 12% | 20% |

  云在取景框里大一些（半径 85–115 像素）也差不多（0.5 档 57%），瓶颈是相机的模糊、曝光、噪点叠在一个弱信号上。
  扫描时每帧都用最近 16 帧再试一次，同一个结果出现两次就算数，所以单次 50% 一般几秒内能读出来，但很斜、很糊时会慢。
- 码的强度是外观和好不好扫的取舍：α 0.25 / β 0.6 时看上去和原版复刻几乎一样；α 0.40 / β 0.8 信号强 60%，但能看出一个不动的星形花纹。现在用前者。
- 误读：CRC-8 挡不住所有乱码（大约 1/256 能过），所以同一个结果要出现两次才算；后端对不存在的编号回「过期」，
  扫描页第一次遇到会接着扫，同一个码再被拒才报错。乱码不会消耗那团云的 5 次机会（编号对不上，碰不到它）。
- **还没在真机相机上试过**：真屏幕的亮度、反光、相机自动曝光和训练时的模拟不完全一样；真机上难扫的话，拍几段视频回来接着练，或者调高码的强度。
