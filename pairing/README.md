# 光学配对快速登录（Cuven 粒子码 CPC v1）

要登录的设备（网页版、或者 iPhone 的登录页）显示一团蓝色粒子云；已经登录的 iPhone 扫一下、面容 ID 确认，那台设备就登进同一个账户。
外观参照 Apple 配对时那团粒子云（录屏量出来的：球壳边上密、外面一圈雾、8 秒一折一松、慢慢转）。
Apple 的协议拿不到、也不该照搬，所以**编码、解码、协议全是自己的**：码藏在粒子丝的走向里，相机拍到后用一个小卷积网络（GPU）还原。

```
要登录的设备                         check.cuven.us                      已登录的 iPhone
  POST /pair/open ───────────────▶ 开一团（2 分钟）：id、secret、6 位数字
  画粒子云（id + secret）+ 显示 6 位数字
  POST /pair/wait（长轮询 ≤ 20 秒）◀─┐                                   相机扫到云 → (id, secret)
                                    │ ◀───────────────── POST /pair/peek（带设备令牌）
                                    │                     回：哪台设备、哪里、什么时候 → 确认卡片
                                    │                                     面容 ID
                                    │ ◀───────────────── POST /pair/approve
  回：用户名 + 身份码 + 新设备令牌 ◀──┘                     登录提醒邮件（方式「光学配对」）
```

## 编码（CPC v1）

- **64 位**：配对编号 24 位 + 密钥 32 位 + CRC-8（多项式 0x07）。
- **卷积码** K = 7，生成多项式 171 / 133（八进制），码率 1/2，补 6 个 0 → 140 码位；交织 `k → (k·53) mod 140`。
- **160 个格子**排在 5 圈上（14 / 22 / 30 / 42 / 52 个，各圈错开一点角度），其中 20 个是导频（`i mod 8 = 3`，LFSR 定的正负）——解码时用来找旋转。
  每个格子的位置按编号做一点确定的抖动（不像整齐的表格）。
- **场**：`D(x) = Σ bᵢ·Gᵢ(warp(x))`，每个格子一团 ± 高斯（径向 σ 0.070、切向 σ 是格距的 0.45），先过一个固定的正弦扭曲（丝是弯的，不是一圈圈的环）。
- **密度**：`ρ = 球壳(r) ×（1 + 0.22·tanh(D/0.30)）×（1 + 2.4·覆盖度²·exp(−(D/0.07)²)）`。
  D 的零线（正负两团挨着的地方）上粒子扎堆成丝，正的一侧略密：码藏在丝的走向里。球壳：r ≤ 1 时 `1 + 0.9r³`（边上亮），外面一圈雾到 1.6。

## 显示（GPU）

几万个粒子全在显存里，每帧走一步朗之万：`x += ε∇log ρ + √(2ε)·ξ + κε(∇log ρ)⊥`。前两项让分布始终是 ρ（相机读得出来），
最后一项沿等密度线流动：丝在「流」，分布不变。8 秒一呼吸（κ 跟着变）、每秒转 0.06 弧度。iOS 用 Metal（`pair_step` + 画点），网页用 WebGL2（transform feedback）。
**y 朝下画**：和相机拍屏幕（行号往下）同一手性；反过来就是镜像，解不出来。

## 解码（扫描端）

1. 相机 1920×1080 BGRA → GPU 裁正中间的正方形、缩成 256²，算「蓝色程度」`clamp((B − R)·1.6)`（白底黑底都适用）。
2. **找框**（v1.1）：减背景（20% 分位 + 0.04）算矩得粗椭圆；24 条射线找亮边的半高点（亚像素）；最小二乘拟合中心 + 2×2 映射，去掉最差 4 个点再拟合；
   除以 `edgeK`（半高处 / 真半径）；最后用极分解去掉映射里的旋转——角度 0 永远对着画面的 x 方向，前后几帧对齐，才能取平均。
3. 极坐标展开 24 × 192（半径 0.10–1.08），每张自己归一，加一个「半径」通道。
4. **网络**（`PairNet`，约 3.2 万参数）：7 层 3×3 空洞卷积（角向首尾相接、径向补 0）+ ReLU，1×1 + tanh，输出每个点的 `tanh(D/0.35)`。在 Metal 上逐层跑，没有 Metal 时退回 CPU。
5. 前后几帧的网络输出取平均；对所有 192 个旋转一起做**最小二乘解卷**（格子模板的 Gram 矩阵 + 0.001 的正则，先求逆）得到 160 个格子的软值。
6. 导频相关度最高的 3 个旋转依次试 Viterbi → CRC；同一个结果连着两次才算数。

## 训练

```
cd pairing/py
python3 train.py 3000                     # 从头练（CPU 就够：约 1 秒一步）
python3 train.py 2000 ../model/cpc1.pt    # 接着练（难度从 0.75 开始）
python3 eval.py                           # 端到端解码率 + 截图解码
```

训练数据全是合成的：随机码 → ρ → 撒粒子 → 模拟相机（透视 / 倾斜 ≤ 40°、失焦、手抖、曝光、伽马、摩尔纹、反光、噪点）→ 找框 → 极坐标；目标是真位置上的 `tanh(D/0.35)`。

## 后端（check.cuven.us）

| 接口 | 谁调 | 说明 |
| --- | --- | --- |
| `POST /pair/open {device?}` | 要登录的设备 | 开一团：`{id, secret, poll, code, ttl: 120, exp}`。同一 IP 每分钟最多 12 次 |
| `POST /pair/wait {id, poll}` | 要登录的设备 | 长轮询 ≤ 20 秒：`status` 是 `open / approved / expired / cancelled`；批准后回用户名、邮箱、身份码（`c1.…`）和这台设备的设备令牌 |
| `POST /pair/cancel {id, poll}` | 要登录的设备 | 关掉 |
| `POST /pair/peek {id, secret \| code, device}` | 扫描端 | 先看是哪台设备（设备、位置、IP、时间），不改状态 |
| `POST /pair/approve {id, secret \| code, device}` | 扫描端 | 面容 ID 之后批准；给账户发登录提醒邮件（方式「光学配对」） |

- 状态存在 R2（强一致）：`pair/<id>.json`、`pair-code/<6 位>.json`；2 分钟过期，密钥错 5 次作废。建议给这两个前缀配一条 R2 生命周期规则（1 天后删除）。
- **设备令牌** `d1.<用户名>.<设备号>.<到期>.<签名>`（HMAC，`SESSION_SECRET`，180 天，可以按设备号吊销）：密码登录、邮箱验证码登录时带 `device: true` 就领一枚，iOS 存钥匙串。
  批准必须带令牌（每台设备 10 分钟最多试 20 次）——光凭扫到的码不能批准。没有令牌的（以前登录的、面容 ID 登录的）扫描前先用密码或邮箱验证码验证一次。
- 安全上：码只活 2 分钟、32 位密钥只能试 5 次、批准要已登录设备的令牌 + 面容 ID，并且批准前确认卡片上能看到是哪台设备、在哪里。
  6 位数字是相机不方便时的手动方式（同样要令牌和面容 ID）。

## 入口

- 网页版登录框：「用 iPhone 扫描登录」→ 粒子云 + 6 位数字；批准后自动登录，设备令牌存在 `localStorage`（`cuven_pair_device`）。
- iOS 登录页：「用 iPhone 扫描登录」（这台 iPhone 显示，另一台已登录的扫）。
- iOS 账户页 → 安全：「扫描登录其他设备」→ 相机 → 确认卡片 → 面容 ID → 批准。账户页的登录方式显示「光学配对」。
- 自检：Debug 构建带 `-CuvenPairLab YES` 启动打开自检页（编码对照测试向量、Viterbi、离屏 Metal 画一团云再用 GPU 网络解出来）；
  `DuoUnfoldedTests.testPairLab` 在 iPad 模拟器上跑一遍，截图 `duo-4s-pair-lab`。

## 现在验证到哪一步

- 合成相机图上的完整解码率（100 个随机码；「4 帧」是手机拿稳、连着 4 帧的网络输出取平均，扫描时就是这样做的）：

  | 相机条件（训练用的难度） | 单帧 | 4 帧 |
  | --- | --- | --- |
  | 0.5（正常拿着对准） | 83% | 97% |
  | 0.75（斜一些、糊一些） | 60% | 73% |
  | 1.0（斜 40°、失焦、手抖、反光都拉满） | 39% | 48% |

  扫描时每秒几十帧、一直在试，单帧的成功率不用很高；真机上对准多久能读出来还没测过。
  在已有网络上接着练 2000 步没有再变好（上面是接着练之后的数），瓶颈在难的相机条件本身，不是训练不够。
- 误读：CRC-8 挡不住所有乱码（大约 1/256 能过），所以同一个结果要连着两帧才算；后端对不存在的编号回「过期」，
  扫描页第一次遇到会接着扫，同一个码再被拒才报错。乱码不会消耗那团云的 5 次机会（编号对不上，碰不到它）。
- 网页 WebGL 画出来的云截图、iOS 自检页离屏 Metal 画的云都能解出来。
- **还没在真机相机上调过**：真屏幕的亮度、反光、相机自动曝光和训练时的模拟不完全一样，可能要收集几张真机照片再微调（`train.py` 接着练）。
